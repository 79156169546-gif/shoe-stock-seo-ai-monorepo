# Карусели

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Как собрать Instagram-карусель без единой платной генерации: тема или ссылка → Claude Code пишет копирайт под каждый слайд и вёрстку → на выходе готовые PNG 1080×1350. Визуал и стиль — твои, Claude их усиливает текстом и структурой, не подменяет.

## Что это даёт

Даёшь тему или ссылку на статью/пост — Claude Code сам пишет копирайт под каждый слайд (заголовки, подписи, цифры) и собирает вёрстку в твоей палитре и шрифтах. Ты не открываешь фигму и не платишь за картинки: карусель рендерится из HTML локально, за секунды, за 0 ₽. Меняется тема — процесс тот же.

## Что понадобится

*  Node.js  — чтобы запустить скрипт сборки (`node build.mjs`), в нём почти нет зависимостей, только `node:fs`/`node:child_process`.
*  Google Chrome  — рендерит HTML-слайд в PNG в headless-режиме. Путь по умолчанию: `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` (macOS).
*  Шрифты  — 1–2 файла `.ttf` под свой стиль (дисплейный заголовочный + текстовый), лежат локально и подключаются как `@font-face` через base64. Взять с Google Fonts под свою тему (не обязательно Unbounded/Inter — это наш выбор, у тебя может быть другой).
*  macOS `sips`  — даунскейл PNG после рендера в 2× (для чёткости). На Linux/Windows аналог — `ffmpeg -vf scale=1080:1350` или ImageMagick `magick -resize`.

Никаких API-ключей и подписок — весь пайплайн работает офлайн.

## Как это работает

Правило простое:  синтез один раз, размножение локально.  Платных шагов в этом пайплайне нет вообще (в отличие от вариантов с AI-фото) — вся картинка собирается HTML/CSS-слоем: фон, карточки, цифры, стрелки, бейджи рисует браузер, а не нейросеть.

Цепочка:

* Claude Code пишет копирайт по слайдам (текст = основной груз карусели, картинка — просто фон/атмосфера).
* Копирайт ложится в HTML-компоненты (один `<section class="slide">` на слайд, общий `<style>` с палитрой и шрифтами через `@font-face`).
* Headless Chrome открывает каждый HTML-файл и делает скриншот 1080×1350 в 2× масштабе (`--force-device-scale-factor=2`) — так текст рендерится чётко, без размытия при последующем сжатии.
* `sips` (или `ffmpeg`) даунскейлит 2×-скриншот до финальных 1080×1350.
* На выходе — пронумерованные PNG (`slide-01.png` … `slide-NN.png`), готовые к загрузке в Instagram.

## Пошагово в Claude Code

1. Дай Клоду тему.  Пример промпта:

Собери карусель для Instagram* на тему «как я веду 5 проектов один, без найма». Формат 1080×1350, 7–8 слайдов. Копирайт — инфостиль: один тезис на слайд, крупный заголовок, короткая расшифровка снизу, без маркетинговых антитез («не X, а Y») и без AI-хуков. Палитра и шрифты — как в `carousels/14_solo-company/build.mjs`, возьми его за образец вёрстки. Сначала покажи копидек текстом на утверждение, вёрстку и рендер — после моего ОК.

2. Клод присылает копидек  (текст каждого слайда — заголовок, подзаголовок, badge-метка) отдельным сообщением, без HTML. Ты читаешь, правишь формулировки, говоришь «ок».

3. Клод верстает HTML-компоненты  — каждый слайд как функция/шаблон, общий CSS с твоей палитрой, шрифты через `@font-face` (base64, чтобы не тянуть внешние файлы при рендере).

4. Клод запускает рендер  — `node build.mjs`, на выходе `out/slide-01.png … slide-NN.png`.

5. Ревью пачкой  — смотришь все слайды разом (Finder/Preview), просишь точечные правки (шрифт крупнее, отступ, цвет карточки) — Клод правит HTML и перерендеривает. Это дёшево: правки — секунды, не новые платные генерации.

Мини-скелет `build.mjs` (рабочий, сократи/расширь под свою тему):

```
import { readFileSync, writeFileSync, mkdirSync } from 'node:fs';
import { execFileSync } from 'node:child_process';

const DIR = import.meta.dirname;                 // папка карусели
const CHROME = '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome';
const font = readFileSync(`${DIR}/../_assets/fonts/Unbounded.ttf`).toString('base64');
mkdirSync(`${DIR}/out`, { recursive: true });

// ——— слайды: массив HTML-фрагментов ———
const slides = [
`<section class="slide cover">
<h1>Один человек теперь может заменить компанию</h1>
<div class="sub">Показываю, как веду 5 проектов один — на нейросетях</div>
</section>`,
`<section class="slide">
<div class="badge">ШАГ 1</div>
<h1>Собираешь второй мозг</h1>
<div class="p">Все проекты и решения — в одной базе, к которой обращается ИИ.</div>
</section>`,
// … остальные слайды
];

const css = `
@font-face{font-family:'D';src:url(data:font/ttf;base64,${font}) format('truetype');}
*{margin:0;padding:0;box-sizing:border-box}
.slide{width:1080px;height:1350px;background:#0E0F12;color:#F2F3F5;
font-family:'D',sans-serif;padding:64px}
h1{font-size:80px;line-height:1.05}
.badge{color:#FF7A1A;font-weight:700;margin-bottom:24px}
.sub,.p{font-size:38px;color:#8A8F98;margin-top:24px}
`;

const page = html => `<!doctype html><html><head><meta charset="utf-8">
<style>${css}</style></head><body>${html}</body></html>`;

slides.forEach((s, i) => {
const n = String(i + 1).padStart(2, '0');
const f = `${DIR}/out/slide-${n}.html`;
writeFileSync(f, page(s));
execFileSync(CHROME, ['--headless=new', '--disable-gpu', '--hide-scrollbars',
'--force-device-scale-factor=2', `--screenshot=${DIR}/out/slide-${n}@2x.png`,
'--window-size=1080,1350', `file://${f}`], { stdio: 'ignore' });
execFileSync('sips', ['-z', '1350', '1080', `${DIR}/out/slide-${n}@2x.png`,
'--out', `${DIR}/out/slide-${n}.png`], { stdio: 'ignore' });
console.log('rendered', n);
});
```

Запуск: `node build.mjs` — на выходе `out/slide-01.png … slide-NN.png`, готовые к загрузке.

## Правила дизайна и копирайта

Сжатая выжимка (полная версия — `RULES.md` в папке `carousels/`):

*  Карусель = гайд, который хочется сохранить , не «красивые картинки с тремя словами». Если слайд не несёт пользы — он лишний.
*  Один тезис на слайд , 7–8 слайдов максимум (дальше не долистают).
*  Иерархия размера:  маленькая метка-kicker → огромный заголовок (суть) → мелкий поясняющий текст → доп. элементы.
*  Один акцентный цвет.  Фон тёмный (или свой брендовый), один яркий акцент на цифры и ключевые слова — не два, без градиентов «инфобиза».
*  Шрифты в 2–3 роли:  заголовочный дисплейный (крупно, плотный трекинг) + текстовый + опционально моно для номера слайда/датастампа.
*  Обложка = боль + обещание  — видно, зачем листать. Финальный слайд — одно CTA («сохрани» / «подпишись» / ссылка в шапке профиля), без флекса личными цифрами.
*  Инфостиль:  просто, по делу, факты и цифры. Объяснять механизм, а не лозунг.
*  Гардрейлы жёстко:  без антитезы «не X, а Y», без «это не реклама — это…», без риторики «а что если…?», без штампов «давайте разберём», без AI-хуков «открыл удивительную тайну…». Эмодзи — только 👇 на ссылке.
*  Числа — реальные.  Число-герой — метрика конкретного проекта, не личный тотал (доход/подушка).

## Грабли

*  `@font-face` только через base64/`file://`  — headless Chrome без интернета не подтянет шрифт по обычному `url()`, если файл не встроен или не указан локальным путём.
*  Рендерь в 2× и потом даунскейль , а не сразу в 1080×1350 — иначе текст на выходе мылится. `--force-device-scale-factor=2` + `--window-size=1080,1350` → скриншот 2160×2700 → `sips -z 1350 1080`.
*  `--headless=new` , не старый `--headless` — старый режим на свежих версиях Chrome рендерит шрифты и тени иначе (иногда падает на `@font-face`).
*  Считай слайды до рендера.  Больше 8–9 слайдов — никто не долистает, лучше сократить текст, чем плодить слайды.
*  Не гони батч без одного утверждённого сэмпла  — сверь первый слайд глазами (шрифт подключился, отступы верные, цвет тот), потом рендери остальные.
*  Пути в скрипте — абсолютные.  `execFileSync` с относительными путями к Chrome/шрифтам ловит рабочую директорию скрипта, а не терминала — легко получить «file not found» при запуске не из той папки.

# B-roll: как в Claude Code готовить видео-перебивки для Reels

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Разбираем два рабочих способа набить ролик перебивками — сгенерировать с нуля и вытащить из собственной видеотеки. Оба гоняются прямо в Claude Code.

## Что даёт

Кидаешь Клоду сценарий рилса — на выходе либо готовые промпты под генерацию кадров и видео на каждую сцену, либо конкретные тайкоды из твоих же скринкастов и съёмок, которые ложатся под текст. Без ручного перелистывания часового скринкаста в поисках нужного момента и без пустого «а что бы такое сюда вставить».

## Что понадобится

*  ffmpeg  — нарезка кадров, контактные листы, вырезка кусков.
*  whisper.cpp (локально, бесплатно)  — расшифровка речи на скринкастах с таймкодами. Модель `ggml-large-v3.bin`, бинарник `whisper-cli`.
*  Опционально Higgsfield  (или аналог: fal, прямой Kling) — только для подхода А, генерация кадров и видео.
* Собственная видеотека — `~/Movies` (скринкасты) и `~/Documents/Материалы YT` (съёмки) — для подхода Б.

## Подход А: генерация с нуля

Когда своей фактуры под сцену нет — рисуем. Логика: сценарий делится на сцены, на каждую сцену — 3 промпта:

*  Промпт первого кадра  (image) — что видно в начале сцены.
*  Промпт последнего кадра  (image) — куда сцена приходит.
*  Промпт видео  (image-to-video, first→last) — как первый кадр превращается в последний: движение камеры, действие, свет.

Модели: кадры — Nano Banana Pro (Higgsfield), она же лучше всех держит текст на экране, если он нужен в кадре. Оживление — Seedance/Veo/Kling через Higgsfield (там же дешевле, чем напрямую у моделей). Generate_audio у видео-моделей выключать — свой звук/VO накладывается отдельно.

Пример запроса Клоду:

Вот сценарий рилса (текст ниже). Раздели на сцены по смене мысли/визуала. На каждую сцену дай 3 промпта:
1) first frame (image) — статичная композиция, без движения;
2) last frame (image) — куда кадр приходит к концу сцены;
3) video (image-to-video, first→last) — только кинематика: [движение субъекта] | [движение камеры] | [свет/оптика/зерно], без описания внешности — она уже в кадрах.
Ограничение: сцена держится 2–4 сек, кадр 9:16.

Сценарий: «...»

Модель вернёт таблицу сцена → 3 промпта, дальше — Nano Banana Pro на first/last, видео-модель на анимацию. Перед батчем — 1 сэмпл, не сразу пачка (правило проекта, экономит кредиты).

## Подход Б: своя видеотека (0 ₽)

Реальный рабочий метод — не генерить, а находить. У Кости накоплен каталог из своих скринкастов и съёмок: `video-pipeline/vasin/broll-catalog/`. Индексация идёт один раз (или добавками по мере накопления новых файлов), а дальше Клод просто подбирает клип и таймкод под каждую строку сценария.

### Как устроен каталог

* `index.tsv` — реестр: id (md5 пути) · длительность · разрешение · относительный путь · абсолютный путь.
* `sheets/<id>.jpg` — контактный лист 4×3 (12 кадров по всей длине клипа), визуальный отпечаток.
* `screencasts/<id>.txt` (+`.json`) — расшифровка речи с таймкодами (для скринкастов).
* `screencasts/<id>/<idx>_<ММСС>.jpg` — hi-res кадры скринкаста через равные интервалы, чтобы читать текст на экране.
* `CATALOG.md` — итоговая таблица: id · клип · длительность · ориентация · что на экране · теги · лучшие куски (диапазоны мм:сс).

### Тулы

*  `tools/broll_index.py`  — обходит корни (`~/Movies`, `~/Documents/Материалы YT`), для каждого нового `.mov/.mp4/.m4v` строит контактный лист (`ffmpeg ... fps=12/dur,tile=4x3`) и пишет строку в `index.tsv`. Резюмируемый — уже готовые id пропускает, прогресс переживает обрыв сессии. Мусор (CapCut-кэш, iMovie/FCP-транскоды, backups) отсекается по списку исключений автоматически.
*  `tools/broll_batches.py`  — чистит то, что осталось от мусора и низкого разрешения (<400px по ширине), и режет новые id на батчи по 24 клипа — чтобы разбор листов раздать нескольким субагентам параллельно.
*  `tools/broll_screencast.py <id> [<id>...] [--step 20] [--maxframes 12]`  — усиленный тир для скринкастов: (1) whisper.cpp транскрибирует аудио целиком локально, 0 токенов, CPU; (2) режет hi-res кадры (1280px) через равные интервалы — читать текст на экране. Тоже резюмируемый.
*  `tools/broll_assemble.py`  — склеивает разобранные части (`parts/`, `parts_long/`, `parts_strong/`) в единый `CATALOG.md`, группирует по папкам-проектам, пересчитывает статистику тегов.

### Пошагово в Claude Code

*  Пополнить индекс новыми файлами:

```
cd ~/Projects/vasinki/video-pipeline
python3 tools/broll_index.py
```

*  Найти новые id , которых ещё нет в `CATALOG.md`:

```
cd vasin/broll-catalog
comm -23 <(cut -f1 index.tsv | tail -n +2 | sort) <(grep -oE '^\| [0-9a-f]{8}' CATALOG.md | tr -d '| ' | sort)
```

*  Разобрать листы.  Клод (или субагенты по батчам от `broll_batches.py`) смотрит `sheets/<id>.jpg` и по каждому клипу определяет: что на экране (1–3 предложения), ориентацию, 2–5 тегов из словаря проекта (`#скринкаст #сайт #терминал #claude #агенты #аналитика #лицо #говорящая-голова #broll` и т.д.), лучшие диапазоны мм:сс.
*  Скринкаст оказался важным  (тег `#скринкаст`) → усиленный тир:

```
python3 tools/broll_screencast.py <id> --step 20 --maxframes 12
```

Дальше по кадрам + транскрипту размечаем  какое окно открыто  (свой сайт / Яндекс.Метрика / терминал Claude Code / Obsidian / Telegram и т.д. — таксономия в `docs/rules/video-indexing.md`) на каждом таймкоде — это и даёт монтажу точные врезки.

*  Дописать в `CATALOG.md`  (или прогнать `broll_assemble.py`, если разбор шёл частями).
*  Отдать сценарий Клоду  — простым запросом вида: «Вот сценарий рилса. Подбери из `CATALOG.md` по одному клипу+таймкоду на каждую сцену — grep по тегам и описаниям, для скринкастов сверяйся с `screencasts_*.md` (там точные диапазоны „лучших врезок“)».
*  Вырезать кусок:

```
ffmpeg -ss <старт> -t <длит> -i <путь-из-index.tsv> -c copy cut.mp4
```

(точнее без `-c copy`, если нужен ровный кадр монтажа).

## Грабли

*  Не грузить в контекст весь `CATALOG.md` разом  — файл растёт (300+ клипов), искать через grep по тегам/словам, не читать целиком.
*  Whisper-галлюцинации на тихих клипах  — модель домысливает фразы («редактор субтитров…») там, где речи нет. Такой клип помечать «тихий/без речи», не доверять транскрипту.
*  Переключение окна между кадрами скринкаста  — если смена сайта/приложения попала в промежуток между hi-res кадрами, сверяться с `.txt`-транскриптом или перегонять `broll_screencast.py` с меньшим `--step`.
*  Длинные записи (>5 мин)  — с дефолтным `--maxframes` окна и переключения теряются, поднимать `--maxframes` вверх.
*  Подход А без гейта — риск сжечь кредиты на неутверждённый кадр.  Сначала утвердить first/last frame картинками, потом уже запускать видео-модель (см. `static_gate.py`/`vision_gate.py` в правилах пайплайна, если процесс автоматизирован).
*  Подход Б бесполезен без регулярного пополнения индекса  — если снял новые скринкасты/съёмки и не прогнал `broll_index.py`, Клод их просто не увидит.

# Сценарии Reels

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Как в Claude Code превратить залетевший у конкурентов Reels в свежий сценарий под свой бренд — и собрать видео одним из пяти способов, под задачу.

## Что это даёт

Claude Code делает три вещи подряд, без переключения между инструментами:

*  Находит залетевшее  — сканирует Reels/Shorts конкурентов в нише, выбирает то, что реально набрало охват.
*  Переписывает угол  — не копипаст чужого текста, а свежий сценарий под твой голос, твои цифры, твой опыт. Берётся драматургия (хук → развитие → CTA), не чужие слова.
*  Пишет подпись  с ключевыми словами — под алгоритм и под поиск внутри платформы.

Дальше — развилка:  как  это снять. Пять стилей сборки под разные задачи: от «есть живой чистый дубль» до «нужен охват любой ценой и лица в кадре может не быть вовсе».

## Шаг 1. Сценарий

Найти залетевшее.  Скрейп виральных видео по нише — `video-pipeline/tools/viral_scout.py` (Apify, YouTube-скрейпер + Instagram hashtag-скрейпер, укладывается в free-бюджет ~$5/мес). Смотрим не на лайки, а на соотношение просмотров к размеру аккаунта — это и есть сигнал «залетело».

Разобрать реф покадрово и повторить под себя.  Самый быстрый путь: даёшь ссылку на понравившийся рилз — Claude разбирает его покадрово (сплит экрана, палитра, шрифт и цвет субтитров, ритм склеек, бейджи, CTA) и собирает такой же, но с твоим лицом, скринкастами и голосом. Стек под это:

*  Достать рилз:  Apify (актор `instagram-scraper`, ключ `APIFY_TOKEN`, free ~$5/мес) или подключённый Instagram-коннектор (Composio), или `yt-dlp` с куками браузера. Кладём mp4 локально.
*  Раскадровка:  `ffmpeg` вытаскивает кадры (`-vf fps=2`) и собирает контактный лист (`tile`), детект склеек — `select='gt(scene,0.3)'`; звук → whisper для VO и пословного тайминга.
*  Разбор:  отдаёшь кадры/контактный лист Клоду — на выходе формула монтажа (что за чем, где хук, как оформлены субтитры и переходы).
*  Повтор:  собираешь такой же под себя — дальше по развилке стилей ниже.

Можно и просто словами.  Если возиться с раскадровкой не хочешь — опиши ролик текстом («лицо снизу, скринкаст сверху, циановые субтитры пословно, красный бейдж LIVE, CTA „ссылка в шапке“»), и Claude соберёт по описанию. Я часто так и делаю.

Переписать угол — честно.  Берём драматургию реф-ролика (что за чем идёт, где хук, где поворот), не текст. Заменяем на свою историю: свои цифры, свой инструмент, свой опыт. Если у конкурента «нашла сервис, который заменяет 5 приложений» — у нас «собрал агента, который делает работу, за которую раньше платил фрилансеру». Правда важнее совпадения с трендом.

Хук — число или парадокс в первые 1,5 секунды.  Не «сегодня расскажу про…», а сразу ставка: «80 тысяч → 350 тысяч за месяц» или «я плачу за подписку меньше, чем за кофе». Shorts/Reels ≤22 секунд — держим темп, лишнего разгона нет.

CTA  — конкретное действие, без «подписывайся, если понравилось». «Гайд в шапке», «ссылка в закрепе», «напиши в комментах слово X» — под формат ролика (см. развилку ниже, у стиля 5 CTA агрессивнее по умолчанию).

Подпись с ключевыми словами.  Первая строка — то, что реально ищут («как настроить агента на Claude Code», «нейросеть для монтажа бесплатно»), дальше — 3–5 хэштегов по теме, без спам-облака из тридцати тегов.

Пример промпта Клоду:

```
Нашёл реф-рилз (расшифровка/раскадровка ниже). Перепиши угол под меня:
я — Костя, веду блог "Васин Константин" про запуск бизнесов на ИИ в одиночку,
голос бренда — честно, цифрами, без инфобиза (см. docs/rules/brand-voice.md).

Реф: [расшифровка/раскадровка].
Мой реальный кейс на эту тему: [факты, цифры, что было на самом деле].

Дай:
1. Хук (число/парадокс, 1.5 сек, без разгона).
2. Сценарий 15-25 сек, короткие фразы под VO.
3. CTA под задачу [подписка / гайд / комментарий].
4. Подпись с ключевыми словами (первая строка — поисковый запрос) + 3-5 хэштегов.
```

## Шаг 2. Развилка стилей — выбери способ сборки

Сценарий готов — дальше решаем,  как  его собрать. Стили параллельны, ни один не отменяет другой — выбор под задачу и под то, что есть на руках (живой дубль или нет, нужен охват или доверие).

### Стиль 2 — разговорный композит

Разговорное видео, но ни секунды статики: ~40% чистая голова, ~50% Костя вырезан по силуэту и посажен поверх фона-вставки (приоритет — реальный скринкаст, потом граф-анимация в бренд-зелёном, потом b-roll), ~10% b-roll во весь экран. Ритм склейки ~2 секунды, смена кадра синхронна фразе. Требует живого чистого голоса — стык звука тут не маскируется клон-дублем. Титры спокойные: серый `#33383D` + зелёный ключевик `#4CAE83`. Полный канон — `docs/rules/style-2-talkinghead.md`.

### Стиль 3 — панчевый монтаж (агент kostya)

Тот же принцип «говорящая голова», но темп инфлюенсерского Reels: клинап пауз и слов-паразитов до WPM ≥190, доля тишины ≤15%. Поверх — дизайнерские caption-движки HyperFrames (субтитр-rail спереди + редкое hero-слово за спиной через matte-вырез, ≤1 на мысль) и motion-графика (счётчики, callout-карточки, badge) на цифрах и ключевых словах. SFX — максимум 2–3 на ролик. Собирает субагент `kostya`, который держит состояние проекта на диске между вызовами. Полный канон — `docs/rules/style-3-montage-agent.md`.

### Стиль 4 — Автостиль

Решает проблему, в которую упирается сборка из обрывков живой речи: микро-обрывы и «сшитость» на стыках. Вместо нарезки — сценарий целиком озвучивается ОДНИМ чистым дублём клон-голоса Кости (Higgsfield, voice_id клона), затем монтаж кладётся свободно поверх под пословный тайминг. Голова вторична (звук не завязан на губы — липсинк не нужен), в кадре в основном композиты поверх скринкастов, как в стиле 2. Самый предсказуемый по звуку способ, когда живого дубля нет или он рваный. Обязательный шаг перед синтезом — разметка ударений (`voicelab/accent.py`), иначе клон ставит их наугад. Полный канон — `docs/rules/style-4-autostyle.md`.

### Стиль 5 — слоп-промо

Формат для холодного охвата, не для основного доверительного контента: горизонтальный сплит кадра 55/45 — сверху оверлеи (накопительный стек иконок инструментов, скролл списка приложений), снизу аватар у микрофона с неоновым бейджем `LIVE`. Двухцветные кинетик-субтитры на шве (связки — белый италик, ключевые слова — бренд-акцент `#FF7A1A` UPPERCASE), кат в такт речи каждую секунду. Аватар — обязательно i2i от реального фото Кости (не генерация с нуля — получается пластик), липсинк только через OmniHuman/Hedra. Грамматику монтажа берём у формата, смысл — свой: честные цифры и реальные проекты, не «comment LINK»-приманка без содержания. Полный разбор — `docs/rules/style-5-slop.md`.

## Шаг 3. Сборка

Общие шаги одинаковы для всех стилей, независимо от развилки:

*  Озвучка.  Живой голос — если чистый непрерывный дубль есть (стиль 2). Клон-голос Higgsfield — во всех остальных случаях (стили 4 и 5, а также стиль 3 при нехватке живого материала). Детали клонирования, разметка ударений, гео-грабли ElevenLabs — отдельный гайд «Клон-голос».
*  Пословный тайминг.  `whisper-cli -ml 1 -oj` по финальной озвучке — секунды каждого слова, под них ставятся титры и шоты.
*  Правило нарезки живого голоса  (если сшиваем стиль 2, не из клона): границы куска — только в паузах между словами, никогда в середине слова. Не тащить «э», «м», «ну», «типа» с краёв куска. Не тащить хвост чужой мысли. После сборки — прогнать whisper по финалу и проверить, что ни одно слово не обрублено.
*  Субтитры  — по канону выбранного стиля: спокойные серо-зелёные (2, 4), дизайнерский rail+motion (3), двухцветный кинетик на шве (5).
*  Рендер под 9:16  — 1080×1920, 30fps, h264, `yuv420p`, `-crf 18 -movflags +faststart`. Готовый файл — в корень `video-pipeline/vasin/`, внутренности монтажа — в свою папку.

## Что понадобится

*  Apify / Instagram-коннектор (Composio) / yt-dlp  — достать реф-рилз для покадрового разбора.
*  ffmpeg / ffprobe  — резка, склейка, звук, рендер, раскадровка рефа (все стили).
*  whisper.cpp  (`whisper-cli` + модель `ggml-large-v3.bin`) — тайминги речи и субтитров, локально, 0 токенов.
*  rembg  (`u2net_human_seg`, CoreML) — вырез человека из фона, стили 2 и 4.
*  Node@26 + `HYPERFRAMES_ROOT`  — движок HyperFrames для стиля 3 (системный Node 20 не подходит, нужен 23+).
*  Higgsfield MCP  (`generate_audio`) — клон-голос Кости, стили 4 и 5.
*  `hedra_talk.py` (OmniHuman)  — липсинк аватара, стиль 5.
*  headless Chrome  — рендер HTML-композиций/оверлеев в PNG, стили 3 и 5.
*  PIL / numpy  — покадровый композит, граф-анимации фона, стиль 2.

Всё локальное — 0 ₽. Платное только там, где явно указано: клон-голос (~$0.02–0.15/ролик) и липсинк OmniHuman (~$2/ролик).

## Грабли

*  Ударения размечать ДО синтеза, всегда.  Без разметки через `accent.py` клон-голос ставит ударения наугад — готовый брак слышен сразу.
*  ElevenLabs напрямую не работает  — гео-блок отдаёт 302. Только через Higgsfield MCP.
*  Node системный 20 не тянет HyperFrames  — нужен Node@26 в PATH, иначе скилы не находят CLI.
*  Голова в стиле 4 кропится честным 9:16 , иначе при масштабировании сплющивает по горизонтали.
*  Кадры — сквозным счётчиком, не по абсолютному времени  (стиль 4): дырка в нумерации на стыке — и ffmpeg обрывает рендер.
*  Громкость нормировать по-сегментно, не одним проходом на всю склейку.  Клон-реплики и живые куски съёмки звучат по-разному — на слух прыгает, если гнать один `loudnorm` на весь ролик (грабля стиля 3).
*  Маска rembg дрожит по кадрам.  Для чернового демо это нормально, для финала — апгрейд на RVM (темпоральная маска), иначе край силуэта «дышит».
*  Не генерить аватар для стиля 5 с нуля  — выходит пластиковое лицо. Только i2i от реального фото + антислоп-промпт («preserve skin texture, no smoothing, not AI»).
*  wan2_7 — плохой липсинк рта.  Для говорящей головы держим только OmniHuman через Hedra.
*  Стиль 5 снижает доверие, если контент нечестный.  Грамматику формата берём, «слоп»-смысл — нет: держим для холодного охвата, не для основного контента бренда.
*  Правило слов важнее любого стиля.  Небрежная нарезка (обрубленное слово, непрочищенный паразит) слышна мгновенно и убивает ролик вне зависимости от того, насколько круто выглядит motion-графика вокруг.

# Клон-голос

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Как локально клонировать свой голос и озвучивать ролики — бесплатно, без токенов, без подписки, без интернета.

## Что это даёт

Это ровно то, что было обещано в посте t.me/vasin_launch/184: локальная генерация голоса на модели  Qwen3-TTS-1.7B . Даёшь модели 10 секунд своего голоса — дальше она озвучивает любой текст твоим тембром, сколько угодно раз. На Mac (M-серия) 10-секундный референс превращается в 30-60 секунд готового аудио за один прогон. На Windows нужна видеокарта от 8 ГБ видеопамяти.

Что важно:

*  Бесплатно.  Модель открытая, весит ~4 ГБ, качаешь один раз.
*  Локально.  Всё считается на твоей машине — ни текст, ни голос никуда не уходят в интернет.
*  Безлимитно.  Один раз склонировал голос — генерируй хоть сто роликов, без счётчика токенов и месячных лимитов подписки.
*  Приватно.  Твой голос не лежит на чужом сервере.
* Поддержка русского и ещё ~10 языков.

Расплата за бесплатность — качество чуть ниже топовых платных клонов (ElevenLabs через Higgsfield) и капризные ударения, которые надо проверять глазами. Ниже — рабочий рецепт, который эту капризность обходит.

## Что понадобится

*  Железо.  Mac на Apple Silicon (M1 и новее) — работает из коробки на MPS. Windows — нужен GPU с 8+ ГБ видеопамяти (CUDA).
*  Python  3.12 + отдельное виртуальное окружение (venv). Держи его отдельно от других TTS-проектов — `qwen-tts` тянет свою версию `transformers`, которая конфликтует с другими движками (например F5-TTS).
*  Модель  `Qwen/Qwen3-TTS-12Hz-1.7B-Base` — качается через  ModelScope  (хаб Alibaba), не через HuggingFace: с российских IP HuggingFace регулярно обрывает соединение (SSL record layer failure), ModelScope — стабильно.
*  Whisper  (`openai-whisper`) — чтобы расшифровать свой референсный аудиофайл в текст. Веса качаются с Azure CDN, тоже в обход HF.
*  SoX  (`brew install sox` на Mac) — библиотека обработки звука, которую использует `qwen-tts`.
* Опционально:  RUAccent  — для расстановки ударений в тексте (см. раздел «Ударения»).

Модели больше 1.7B у Qwen3-TTS нет — это топ линейки, апгрейдить пока некуда. Для русского клонирования своего голоса это лучшая открытая модель на рынке: по отзывам сходство голоса выше, чем у XTTS-v2 и MiniMax.

## Установка

```
# 1. Отдельное окружение для Qwen (uv быстрее pip, но подойдёт и venv)
mkdir voicelab && cd voicelab
uv venv .venv-qwen --python 3.12
uv pip install qwen-tts modelscope soundfile openai-whisper

# 2. Веса модели — через ModelScope, не HuggingFace
.venv-qwen/bin/modelscope download \
--model Qwen/Qwen3-TTS-12Hz-1.7B-Base \
--local_dir ./qwen3tts-1.7b

# 3. SoX (Mac)
brew install sox
```

Заготовка модели весит ~4.2 ГБ, качается один раз. На Mac M1 Pro загрузка модели в память занимает ~60 секунд (разово на процесс запуска), дальше синтез идёт быстрее.

## Как записать хороший референс

Референс решает качество клона — это единственное, на чём не стоит экономить.

*  10-11 секунд  чистой речи. Без музыки, шума, эха, без пауз в начале/конце.
* Говори живо и разборчиво, как в обычном ролике — модель копирует интонацию, а не только тембр.
* Сохрани как моно WAV, 24 кГц (`ref_kostya.wav`).
* Расшифруй референс в текст — вручную или через whisper:

```
.venv-qwen/bin/whisper ref_kostya.wav --model small --language ru \
--output_format txt --output_dir .
```

Получившийся текст (`ref_kostya.txt`) должен  дословно  совпадать с тем, что сказано в WAV — это и есть «ref_text», по которому модель сверяет звук с текстом.

## Как генерить

Движок — `qwen_gen.py`, обёртка для быстрого вызова — `qvoice.sh`:

```
./qvoice.sh "Текст для озвучки"                  # референс по умолчанию
./qvoice.sh "Текст" my_voice.wav my_voice.txt     # другой голос
OUT=~/Downloads/итог.wav ./qvoice.sh "Текст"      # свой путь вывода
```

Под капотом — один вызов модели:

```
wavs, sr = model.generate_voice_clone(
text=text,
language="Russian",
ref_audio=ref_audio,
ref_text=ref_text,
)
```

На Apple Silicon: `device="mps"`, `dtype="float16"`, `attn_implementation="sdpa"` (flash-attn на Mac нет), плюс переменная `PYTORCH_ENABLE_MPS_FALLBACK=1` — неподдержанные операции тихо уходят на CPU вместо падения с ошибкой.

Рабочий рецепт, проверенный боем:

*  Генерь по предложениям, не одним длинным проходом.  Качество Qwen заметно падает после ~300 слов за один вызов — режь текст на фразы/предложения и синтезируй каждую отдельно.
*  Текст — чистый , без лишней разметки (см. «Грабли» ниже).
*  Три дубля на выбор.  Qwen недетерминирован — один и тот же текст каждый раз звучит чуть иначе. Сгенерируй 3 варианта одной загрузкой модели и выбери лучший на слух:

```
.venv-qwen/bin/python reel_qwen_takes.py ref_kostya segments.txt out 3
```

где `segments.txt` — список фраз построчно, `3` — число дублей. Скрипт сам:

* убирает призвуки/тишину с краёв каждой фразы (порог амплитуды + отступ 25 мс),
* добавляет короткий фейд (9 мс) на границах — убирает щелчки на стыках,
* склеивает фразы с микропаузой ~0.24 секунды между ними — это даёт естественный ритм речи вместо слипшегося потока.

## Ударения

Русский — главная боль всех открытых TTS: омографы («за́мок» vs «замо́к») путают все модели, включая Qwen, потому что их не учили на текстах с проставленными ударениями.

*  В сам текст синтеза метки ударения совать не надо  — Qwen не обучен на них и от разметки речь становится хуже, а не лучше.
* Рабочий путь — держать словарь опасных слов и переформулировать фразу, если модель путает ударение, либо (что надёжнее) размечать ударения в  ref_text  — референсном тексте, на котором модель «учится» слышать ударные гласные для конкретного слова.
* Для расстановки ударений в тексте есть `accent.py` на движке RUAccent (turbo3.1, с контекстным разрешением омографов):

```
.venv-qwen/bin/python accent.py "Текст для проверки" --form plus
```

*  Обязательно проверяй результат глазами  до синтеза — так проще поймать ошибку, чем потом ловить её на слух в готовом аудио.
* Если ударения критичны, а Qwen упрямо ошибается — запасной вариант: облачный клон голоса через ElevenLabs (доступен на подписке Higgsfield). Там разметка ударения комбинирующим акутом (U+0301) действительно работает и слушается моделью — но это уже не бесплатно и не офлайн.

## Грабли

*  Метки ударения (`+`, U+0301) и КАПС в тексте синтеза ломают Qwen  — не сглаживают произношение, а вызывают заикания и сбитые ударения. Модель их не понимает, потому что не обучена на размеченных текстах. Если слово произносится неправильно — переформулируй фразу или поменяй слово, не вставляй метку.
*  Недетерминизм.  Один и тот же текст на одном и том же референсе каждый раз звучит немного иначе — поэтому и нужны 3 дубля с выбором лучшего, а не один прогон.
*  Качество падает на длинном тексте.  После ~300 слов за один вызов модель начинает «плыть» — режь на предложения.
*  HuggingFace с российских IP флапает  — качай веса и whisper через ModelScope/Azure CDN, не через HF напрямую.
*  Не смешивай venv разных TTS-движков  — `qwen-tts` требует свою версию `transformers`, конфликтует с F5-TTS и другими.
* Референс хуже 10 секунд или с шумом/музыкой — клон получится смазанным, тут экономить нельзя.

# Авто-монтаж

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Как в Claude Code собрать монтаж ролика кодом — локально, без монтажёра и без CapCut. Claude режет дорожку по паузам между словами → ставит анимированные субтитры и графику → рендерит финал под Reels. Весь монтаж — кодом.

## Что даёт

* Ноль ручной резки в таймлайне. Границы кусков считает whisper по паузам между словами — не «на глаз».
* Субтитры и motion-графика — не наложение в редакторе, а рендер из HTML/ffmpeg по точным таймкодам слов.
* Финал сразу в формате Reels: 1080×1920, 30fps, h264, готов к заливке.
* 0 ₽ за монтаж. Все инструменты локальные (ffmpeg, whisper.cpp, Remotion/HyperFrames). Платный шаг — только если нужен клон-голос или ИИ-B-roll, и это отдельный гейт.

## Что понадобится

Инструмент  Зачем      `ffmpeg` / `ffprobe`  резка, склейка, звук, формат под Reels    `whisper.cpp` (`whisper-cli` + модель `ggml-large-v3.bin`)  пословный тайминг речи — на нём держится вся резка и субтитры    Node.js (опц., Remotion)  рендер караоке-субтитров через `captions.py`    Node@23+ (опц., HyperFrames)  дизайнерские анимированные субтитры + motion-графика (стиль 3)    Python venv проекта  обвязка (`tighten.py`, `transcribe.py`, `captions.py`)

Всё это уже стоит в `video-pipeline/` (папка `VP`, венв `source .venv/bin/activate`). Ничего платного качать не нужно.

## Шаг 1 — транскрипт с пословным таймингом

Без этого шага резать по паузам нечем — whisper обязателен и первый.

```
ffmpeg -i in.mp4 -ar 16000 -ac 1 -c:a pcm_s16le /tmp/a.wav
whisper-cli -m ~/.whisper-models/ggml-large-v3.bin -f /tmp/a.wav -l ru \
-ml 1 -sow -oj -of /tmp/words
```

`-ml 1 -sow` — режим «одно слово = один сегмент», `-oj` — JSON с таймкодами `from/to` в миллисекундах. Готовая обёртка в проекте — `tools/transcribe.py`, она же умеет облачный Groq whisper (лучше держит русский, нужен ключ) или чисто офлайн whisper.cpp:

```
python tools/transcribe.py --in in.mp4 --out words.json --engine whisper-cpp --lang ru
```

Результат — плоский список `[{"w": "слово", "start": 1.23, "end": 1.41}, ...]` в секундах. Это единый источник правды для резки, субтитров и QA-проверки готового ролика.

Промпт Клоду:  «Сделай пословный тайминг для `in.mp4` через `tools/transcribe.py`, движок whisper-cpp, результат в `words.json`».

## Шаг 2 — реза по паузам (что удаляем)

Правило Кости: главное в монтаже — сами слова и точность нарезки. Небрежная склейка слышна сразу.

Что вырезаем:

*  мёртвые паузы  — тишина внутри фразы длиннее ~0.35–0.6с (реальная пауза дыхания/мысли, не пауза между словами);
*  слова-паразиты и заполнители  — «э», «м», «ну», «вот» (как затычка), «типа», «короче», «значит», «как бы»;
*  брак и хвосты чужой мысли  — если после нужной фразы пошло «то есть...» или «у меня есть...» — обрезаем до этого места, кусок = ровно одна законченная мысль;
*  дубли и оговорки  — если фраза сказана дважды, оставляем чистый дубль.

Чего не делаем никогда: не режем  внутри слова . Граница куска — только пауза между словами, проверяется по `words.json` (старт куска ≥ начала первого слова, конец ≤ конца последнего). Обрубок вроде «полдн[я]» или «[п]однимать» слышен как дефект и убивает ролик.

Автоматическая резка по реальной тишине (не завязана на распознавание слов, быстрый первый проход):

```
python tools/tighten.py --in cut.mp4 --out tight.mp4 \
--noise -30dB --min-sil 0.35 --pad 0.07
```

Тул гоняет `ffmpeg silencedetect`, находит интервалы тишины длиннее `--min-sil`, оставляет по `--pad` секунд тишины на стыке (гасит щелчок) и склеивает через `filter_complex trim/concat`. Для паразитов и хвостов мысли, которые тишиной не поймать (слово произнесено, но лишнее), режем руками по `words.json` — задаём точные `start/end` нужных кусков и склеиваем `ffmpeg -f concat`.

После сборки — обязательно прогнать `transcribe.py` по финалу ещё раз: все слова целы, паразитов нет, ничего не обрублено. Чистые границы (пауза, а не слово) дают плавную склейку сами по себе — кроссфейд 20–60мс нужен только как страховка.

Промпт Клоду:  «Прогони `tighten.py` по `cut.mp4` с `--min-sil 0.35`, потом сверь результат с `words.json` — убедись, что ни один рез не попал внутрь слова, и вырежи вручную паразиты “э/ну/короче” по таймкодам».

## Шаг 3 — субтитры (караоке или кинетик)

Два готовых движка, оба локальные, оба берут тот же `words.json`.

Караоке-субтитры (Remotion, стиль 1/2)  — текущее слово подсвечивается, как в CapCut/Submagic:

```
python tools/captions.py --in tight.mp4 --out final_subs.mp4 --words words.json
```

Стиль (шрифт, цвет, кегль) правится прямо в `captions/src/Captions.tsx`, превью — `pnpm studio`. Опции: `--words-per-phrase` (сколько слов на экране разом), `--accumulate` (слова копятся фразой), `--hook` (хук-карточка на первый экран), `--montage` (b-roll врезки + пунш-зумы по JSON-манифесту).

Пример ASS-субтитров (готовый файл, если рендерить не Remotion, а прямым `ffmpeg ass=`, как в `build_reel.sh`):

```
[Script Info]
PlayResX: 1080
PlayResY: 1920

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, Bold, Alignment
Style: Default,Arial Bold,64,&H00E6FFFF,1,2

[Events]
Format: Layer, Start, End, Style, Text
Dialogue: 0,0:00:01.20,0:00:01.60,Default,,{\1c&H00E6FFFF&}СОБРАЛ
Dialogue: 0,0:00:01.60,0:00:02.00,Default,,{\1c&H00E6FFFF&}РОЛИК
```

Каждая строка — таймкод из `words.json`, слова группируются по 2–4 в фразу.

Дизайнерские кинетик-субтитры + motion-графика (HyperFrames, стиль 3)  — панчевый рилз с caption-движками (rail-субтитр + hero-слово за спиной через matte-вырез) и motion-блоками на числах (counter/callout/cards/badge). Тяжелее по сетапу (нужен Node 23+, matte через u2net на CPU ~2fps), но даёт «инфлюенсерский» ритм. Держит скилл `embedded-captions`, каталог из 25+ визуальных идентичностей — дефолт бренда `loud` (Anton, слэм), строгий вариант «читать каждое слово» — `anchor`. Подробно — `docs/rules/style-3-montage-agent.md`.

Для авто-монтажа кодом без агента-художника достаточно первого варианта — он полностью управляется CLI-командой и не требует ручной вёрстки кадров.

Промпт Клоду:  «Наложи караоке-субтитры на `tight.mp4` через `captions.py`, слова бери из уже готового `words.json`, 3 слова на фразу».

## Шаг 4 — графика/overlay

Отдельным слоем поверх видео кладём то, что не входит в субтитры: скринкаст-инсет, второй видеопоток (голова + вставка), LIVE-бейдж, статичный фон. Собирается фильтр-графом `ffmpeg` — без таймлайна, координаты и таймкоды заданы числами.

Живой пример из `build_reel.sh` — три слоя (фон, скринкаст сверху, лицо снизу) + бейдж + субтитры + звук одной командой:

```
ffmpeg -v error -y \
-i top.mp4 -i face.mp4 -loop 1 -i live_badge.png -i vo_master.mp3 \
-filter_complex "\
color=c=#0a0a0a:s=1080x1920:d=$DUR[bg]; \
[1:v]scale=1080:1280:force_original_aspect_ratio=increase,crop=1080:1280,setsar=1[face]; \
[0:v]scale=1080:640:force_original_aspect_ratio=increase,crop=1080:640,setsar=1[top]; \
[bg][top]overlay=0:0:shortest=0[a]; \
[a][face]overlay=0:640[b]; \
[b][2:v]overlay=W-w-34:26[c]; \
[c]ass=captions.ass:fontsdir=fonts[v]" \
-map "[v]" -map 3:a -t $DUR \
-c:v libx264 -pix_fmt yuv420p -r 30 -c:a aac -b:a 192k out.mp4
```

Логика: `color=` создаёт фон нужного размера → каждый источник `scale+crop` под свой блок кадра → `overlay=x:y` кладёт слои друг на друга по координатам → `ass=` в конце цепочки жжёт субтитры прямо в кадр. Порядок `overlay` важен — верхний слой в команде оказывается визуально сверху.

Для motion-графики (счётчики чисел, callout-карточки, бейджи под ключевые слова) — HyperFrames-скиллы `embedded-captions`/`motion-graphics` (стиль 3): блоки 2–5с вне зоны лица, палитра жёлтый/красный, рендерятся из HTML через headless Chrome, а не ffmpeg-фильтрами.

Промпт Клоду:  «Собери overlay: скринкаст сверху (640px), лицо снизу (1280px), LIVE-бейдж в правом верхнем углу, звук из `vo_master.mp3`, субтитры из готового `.ass` — как в `build_reel.sh`».

## Шаг 5 — рендер под Reels

Финал всегда 1080×1920, 30fps, h264, `yuv420p` (иначе не проигрывается в части плееров), быстрый старт для стриминга. Нормализация каждого куска перед склейкой — обязательна, иначе `concat` рвёт поток:

```
ffmpeg -i seg.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2" \
-r 30 -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a aac -ar 44100 seg_n.mp4
```

Финальный рендер (пример команды сборки из `build_reel.sh`, точный формат для сдачи):

```
ffmpeg -v error -y \
-i top.mp4 -i face.mp4 -loop 1 -i live_badge.png -i vo_master.mp3 \
-filter_complex "...весь граф из шага 4..." \
-map "[v]" -map 3:a -t $DUR \
-c:v libx264 -pix_fmt yuv420p -r 30 -c:a aac -b:a 192k "$OUT"
```

`-t $DUR` фиксирует точную длину ролика, `-map 3:a` берёт звук из четвёртого входа (VO), а не из видеодорожек. Готовый файл — в корень `vasin/`, черновики и промежуточные `_*.json`/кадры — в подпапку с названием видоса.

Промпт Клоду:  «Отрендери финал под Reels из собранного графа, длина ровно `$DUR` секунд, 1080×1920/30fps/h264, положи в `vasin/<видос>_v1.mp4`».

## Грабли

*  Резать не по слову, а по паузе.  Старт/конец куска обязательно сверять с `words.json` — иначе слышен обрубок звука. Это правило №1, все остальные — вторичны.
*  Не тащить брак.  Оговорки, повторы дубля, паузы >0.6с внутри фразы, хвост чужой мысли после нужной фразы — вырезать, не «сгладить» кроссфейдом.
*  Нормализовать перед `concat`.  Разные fps/pix_fmt/разрешение кусков → `ffmpeg concat` рвёт видео без явной ошибки (либо падает, либо портит звук). Прогонять через одинаковый `scale+pad+crf` до склейки.
*  Ровная громкость по сегментам, не по всему ролику.  Один `loudnorm` на всю склейку не спасает, если куски из разных источников (клон-голос и реальная съёмка звучат по-разному) — нормировать каждую реплику отдельно `loudnorm=I=-16:TP=-1.5` до склейки.
*  Whisper на английской модели ест русский в мусор.  Явно указывать `-l ru` / `--lang ru`, иначе тайминги слов съезжают и резка идёт мимо пауз.
*  QA после сборки — обязателен.  Прогнать `transcribe.py` по финалу: слова целы, бренды не искажены, паузы там, где должны быть. Без этого шага брак уходит в релиз.
*  Финальный формат — жёстко 1080×1920/30fps/h264/yuv420p/`-movflags +faststart`.  Отступление от этого чек-листа — частая причина, почему ролик «не грузится» или дёргается в Reels/TikTok.

Полные каноны стилей — `docs/rules/montage-local.md` (сводный runbook), `docs/rules/style-3-montage-agent.md` (панчевый HyperFrames-монтаж), `docs/rules/style-4-autostyle.md` (клон-голос + монтаж поверх, когда живую дорожку резать не хочется вообще).

# Второй мозг на Claude Code

Установка всего набора одной командой: `curl -fsSL https://raw.githubusercontent.com/vasin-k-i/content-pipeline/main/install.sh | bash` — [репозиторий на GitHub](https://github.com/vasin-k-i/content-pipeline)

Каркас памяти для человека, который ведёт несколько проектов через Claude Code и устал каждый раз объяснять заново, что за проект, где ключи и что вчера решили.

## Что это и зачем

Claude Code по умолчанию не помнит ничего между сессиями. Открыл новый чат — рассказывай заново: какие проекты, где домены, что в работе, какие решения уже приняты. При 5–10 проектах это съедает больше времени, чем сама работа.

«Второй мозг» — это не курс про мышление и не философия заметок. Это рабочий каркас: папка `_BRAIN/` с определённой структурой + мост, который автоматически подгружает её в каждую сессию Claude Code + набор скиллов (команд `/что-то`), которые ведут заметки за тебя. Ставится один раз командой в терминале, дальше Claude сам проводит короткое интервью и наполняет каркас твоими данными.

Хранилище — обычный Markdown. Можно открыть как Obsidian-vault, можно просто как папку файлов. Никакой отдельной базы, никакого лок-ина.

## Что даёт

*  Claude не начинает с нуля.  Открываешь новый чат в любой папке — ядро памяти (фокус, проекты, инфраструктура) подгружается автоматически через хук перед первым сообщением.
*  Контент-план, ключи, решения — в одном месте.  Не «где я это записывал», а `_BRAIN/STATE.md` (что в работе), `_BRAIN/STACK.md` (домены/серверы/ключи-указатели), `_BRAIN/Решения/` (почему сделали так, а не иначе).
*  Обратная запись знаний.  Не только читает — по ходу сессии сам дописывает находки обратно в файлы. Факт узнал → в `Заметки/`. Решение принял → в `Решения/`. Сессию закончил → короткий итог в `hot.md`, чтобы следующий чат подхватил с того же места.
*  Токен-эффективно.  В контекст грузится не вся папка, а только «горячее ядро» (несколько небольших файлов). Остальное — по ссылке, Claude идёт туда сам, когда нужно.

## Установка (одна команда)

macOS / Linux, на Windows — через Git Bash:

```
curl -fsSL https://raw.githubusercontent.com/vasin-k-i/second-brain-kit/main/install.sh | bash
```

Что делает команда:

* Скачивает кит и кладёт в `~/.second-brain-kit`.
* Разворачивает каркас `_BRAIN/` в `~/SecondBrain` (можно указать свою папку вторым аргументом). Файлы-шаблоны переименовывает в рабочие — ничего не затирает, если каркас уже стоял.
* Дописывает в `~/.claude/CLAUDE.md` блок моста памяти (между маркерами, идемпотентно — повторный запуск не плодит дублей) со ссылками `@STATE.md` `@STACK.md` и правилами «записывать находки обратно». Существующий `CLAUDE.md` бэкапится в `.bak` перед правкой.
* Ставит SessionStart-хук — движок, который реально подгружает ядро в начале каждой сессии. Без хука мост в `CLAUDE.md` просто лежит мёртвым текстом.
* Раскладывает скиллы (`/capture`, `/find`, `/daily`, `/research` и другие) в `~/.claude/skills/`.

Дальше в Claude Code:

```
/setup-second-brain
```

Claude задаёт несколько вопросов — чем занимаешься, какие проекты, что сейчас в фокусе — и сам заполняет `STATE.md`, `PROJECTS.md`, опционально `STACK.md` (указатели на инфраструктуру, не сами ключи). Углублённый добор позже: `/setup-second-brain --deep`.

## Структура каркаса `_BRAIN/`

Ядро (грузится в каждую сессию, держи компактным):

Файл  Что там      `CONTEXT.md`  Кто ты, фокус, приоритеты — до 100 строк    `STATE.md`  Что сейчас в работе, активные проекты одной строкой    `STACK.md`  Домены, серверы, репозитории, указатели на ключи (не сами ключи)    `PROJECTS.md`  Канбан: цель / шаг / блокеры / статус по каждому проекту    `MEMORY.md`  Индекс доменной памяти — по одной строке на тему    `hot.md`  Автообновляемый кэш «на чём остановились» — руками не трогать    `CRITICAL_FACTS.md`  Совсем горячее — таймзона, роль, что нельзя забыть

Папки (грузятся по запросу, не в каждой сессии):

* `Заметки/` — атомарные факты, методы, цифры с тегами
* `Решения/` — ADR, решения с аргументацией
* `Выводы/` — итоги сессий по датам
* `Стратегии/` — долгоиграющие планы
* `Встречи/` — расшифровки встреч
* `Postmortem/` — разборы провалов
* `Архив/` — неактуальное, но жалко удалять
* `raw/` — сырые источники, не редактируются

## Как пользоваться

*  Ключи, домены, сервера, репозитории, цены на модели → `STACK.md`.  Не переспрашивай себя каждый раз, не гугли заново — сверься туда.
*  Что сейчас в работе → `STATE.md`.  Детали конкретного проекта — в `PROJECTS.md`.
*  Не нашёл в ядре — грепай, не переисследуй.  `rg -i 'ключевое_слово' ~/SecondBrain/_BRAIN`.
*  Любую новую находку пиши обратно, не только в конце сессии.  Факт/метод/цифра → `Заметки/` (первая строка — теги `#источник #тема`). Решение с обоснованием → `Решения/ADR-NNN_слаг_дата.md`. Итог сессии → `Выводы/дата.md`.
*  Секреты в `.md` не пишем.  Только указатель, где лежит ключ (`.env` проекта, менеджер паролей).
*  Даты — ГГГГ-ММ-ДД.  Так они сортируются и ищутся без сюрпризов.

Скиллы поверх каркаса — ставь только нужные: `/capture` `/save` `/find` `/ingest` `/health` (захват и поиск), `/challenge` `/emerge` `/panel` `/connect` (мышление), `/daily` `/recap` `/review` `/decide` (ритм), `/research` (поиск без API-ключей). Отдельно — контентные скиллы (сценарии, Writer, SEO-роли) и модули (видео-пайплайн, работа с сайтами) — их подключаешь по потребности, не всё сразу.

## Обновление

Обновить только скиллы, не трогая уже наполненный каркас:

```
curl -fsSL https://raw.githubusercontent.com/vasin-k-i/second-brain-kit/main/install/install-skills.sh | bash
```

Полное обновление (скиллы + хук + мост памяти, каркас и заметки не трогает):

```
curl -fsSL https://raw.githubusercontent.com/vasin-k-i/second-brain-kit/main/install/update.sh | bash
```

Откатить установку: восстановить `~/.claude/CLAUDE.md` из `.bak` и удалить папку vault, если решил начать заново.

## Грабли

*  Без SessionStart-хука мост не работает.  Блок `@import` в `CLAUDE.md` — это просто текст, пока хук в `settings.json` реально не подгружает ядро при старте сессии. Если после установки Claude «не помнит» — первым делом проверяй хук, не каркас.
*  Ядро держи маленьким.  Если напихать в `STATE.md`/`STACK.md` весь архив вместо однострочников — оно перестаёт быть «горячим», грузится долго и захламляет контекст. Разросшееся — в `Архив/` или `Стратегии/`, не в ядро.
*  Не переизобретай структуру каждую неделю.  `INDEX.md` внутри каркаса — источник истины по тому, что где лежит. Меняешь структуру — правь его, а не заводи параллельную систему папок.
*  Секреты не текст.  Соблазн быстро вписать ключ прямо в заметку, чтобы не потерять, — не делай так: `.md`-файлы синкаются, бэкапятся, иногда оказываются в публичных репозиториях. Пиши только путь до `.env`.
*  Повторный запуск install.sh безопасен , но не «пересоздаёт» — он ничего не затирает, если файл уже существует. Если нужно обновить контент шаблона, а не только скрипты, — правь руками или через `--deep` интервью.
